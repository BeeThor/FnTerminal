# fnOS 安装、升级、卸载与安全验收

以下均是**待在真实 fnOS 上执行的步骤**。填写设备版本/CPU/日期/结果，保留不含密码或令牌的截图和日志。用户已确认本次先自行上传 Intel 包；开发环境未连接 NAS。

## 安装与启动

1. 核对 SHA256，Intel 选择 `FnTerminal-0.9.0-x86.fpk`。应用中心 → 设置 → 手动安装应用 → 上传。0.2.0 已安装时按系统升级流程安装0.6.0。
2. 验证图标与 root logo.png 一致、启停按钮可用、状态正确；点击桌面图标，URL仍在原 NAS 域名的 `/app/fnterminal`。
3. 首次打开应出现SSH弹窗，未创建应用Shell；主机填127.0.0.1、端口填实际值（本次10022）、用户名填自己的NAS用户。连接时按可信来源核对指纹，在终端输入密码。执行 `id; ps -o user,uid,gid,comm -p $$; tty; stty size; printf '中文终端🙂\n'`。应为所填SSH用户；应用中心的服务进程仍是 fnterminal 非0 UID、有真实/dev/pts、中文可见。
4. `sleep 60` 后按 Ctrl+C，验证及时返回提示符；打开 vim/top 验证方向键、退出和屏幕缩放。macOS本机测试不替代这一步。
5. 第七个标签受限；不同标签分别 `echo $$` 应为不同Shell。重命名/锁定/右键重连/复制粘贴/搜索/主题/字号均实测。
6. 滑动移动快捷键栏只能滚动，不得向终端发送方向键或Ctrl+C；轻点只发送一次。iOS Safari、Android Chrome 真实软键盘中文拼音选词、长按粘贴、Ctrl、Tab、方向键、横竖屏、键盘展开/收起。桌面模拟390px仅证明布局，不证明真实输入法。
7. 保存后关闭并重开，自动尝试最近使用的SSH配置；通过＋创建另一连接，通过菜单或标签右键编辑、保存、重连；其他标签应继续运行。验证数字开头用户名、自定义10022端口和错误目标提示。关闭SSH时不应自动打开服务。
8. 高级诊断 → 独立应用账户 Shell 才提供fnterminal提示符；密码和私钥内容不得出现在localStorage、诊断与应用日志，配置仅含名称/主机/端口/用户名。删除最近使用的配置后重新打开应回到配置弹窗；关闭自动连接后不得创建会话。
9. 搜索连接名称/地址/端口/用户名，检查列表选中状态及编辑后“有未保存修改”；保存反馈应显示名称和实际目标，活动会话不变化。浏览器存储被禁用时，页面可打开、可临时连接、不应谎称保存成功。
10. 主机字段填写localhost:10022，应在弹窗提示分开填写且不创建标签；合法IP/IPv6/域名正常使用。配置损坏为null后可恢复默认设置。

## 身份与隔离

1. 未登录访问 HTTP/WS/lease；普通用户访问同样地址；即使桌面图标不可见也直接访问。均不得得到终端或资产。
2. 浏览器WS请求 Origin来自另一个站点、Origin:null、无Origin，后端都拒绝；普通用户即使手工增加X-Trim-*也拒绝。
3. 从NAS普通账户尝试 `curl --unix-socket /var/apps/fnterminal/target/app.sock -H 'X-Trim-Userid:1000' -H 'X-Trim-Isadmin:true' http://localhost/app/fnterminal/`。应为文件权限拒绝或403。root是信任边界外的系统管理员，不用root请求证明普通用户隔离。
4. 检查 Socket 0600；若网关不是root，仅在核实 UID/GID 后配置0660，并重测普通账户及包账户的伪造请求都403。禁止666/777；不能将fnterminal自身UID设为可信网关。
5. 确认正常HTTP与WS网关连接的对端UID与Header覆盖策略。确保客户端X-Trim-*被网关覆盖；确认Host和Origin同源规则在HTTP/HTTPS及远程连接方式中一致。
6. 高级诊断应用Shell中 `printf '%s\n' "${TRIM_API_TOKEN-unset}"` 应显示unset；账户不在sudo/docker组，无默认root能力。用户文件无额外授权。
7. 在高级诊断应用Shell和SSH会话分别测试：保持会话后注销NAS或撤销管理员身份，观察lease请求失败，最迟约60秒关闭PTY；浏览器后台节流可能使会话提前过期，这是失败关闭。

## 回收、重启和负载

1. 在多个标签启动 `sleep 600 &` 和前台管道；在测试机可用setsid时启动 `setsid sleep 600 >/dev/null 2>&1 &`，记录 PID。
2. 分别关闭标签、主动exit、断网、空闲超过15分钟、应用中心停止；检查对应进程消失，其他标签不受单页关闭影响。停止应用后所有包账户的监督器、Shell及其后台任务应消失。
3. 快速开关标签、同时两个管理员创建会话。上限12全局/6每用户，创建和输入超速受限，不产生额外PTY。
4. `yes` 持续输出，浏览器不读/变慢时输出背压，应能停止服务，不增长无界缓冲。不要在真实业务NAS执行fork-bomb。
5. NAS重启后检查运行状态、旧PID/Socket恢复、无重复后台服务。
6. 在隔离测试环境使SSH目标不再响应，观察保活按15秒/3次触发断开；网络、空闲超时、登录态过期、应用停止应显示不同提示，诊断session_end原因应一致。不要在业务NAS随意修改防火墙。

## 升级与卸载

1. 应用账户HOME创建无敏感内容的marker文件。打开活动终端和后台sleep后升级到版本更高的包。
2. 升级前旧终端被回收；旧PID消失；新服务非root、Socket/入口恢复；marker保留。0.2.0/0.3.0故障升级到0.6.0必须另记实测结果。
3. 运行中卸载：系统应先正常停止，无PTY残留，无额外TCP监听、Docker/系统用户组/系统命令链接残留。
4. 数据保留/删除由fnOS应用中心的卸载选择控制，本包不自行递归删除用户数据。分别选择保留和删除，验证HOME/var/etc与系统实际语义，重装后检查是否符合选择。
5. ARM64必须在ARM fnOS另测，不能由x86安装结果替代。

## 故障诊断

终端断连时，先在终端菜单打开“连接诊断与日志”，下载诊断并确认client失败阶段和server事件。

0.6.0应用本身启动失败时，记录应用中心显示的具体生命周期错误，并运行 `scripts/diagnose-fnos.sh` 或至少读取 `tail -n 30 /var/apps/fnterminal/var/fnterminal.log`。该脚本只读文件权限、包进程身份及元信息日志，不输出环境变量/密码。没有这些信息时，不能把“执行应用启动脚本失败”归因于某一个错误。

## 0.7.0连接迁移与误操作验收（真实fnOS待验证）

1. 保存多个连接后导出JSON，在另一浏览器导入；地址/端口/用户名正确，NAS密码不在文件中，重复项跳过。无效/含凭据/超过30条的文件整体拒绝，原有连接保持。
2. 修改表单后切换连接、新建或关闭，选择继续编辑时草稿保留，选择放弃时执行对应动作；不改变后台活动SSH会话。
3. 删除当前配置，点击撤销恢复；有活动终端时删除配置不能关闭该终端。关闭弹窗后撤销记录不保留。
4. 核对诊断摘要的版本/平台/账户/活动会话，事件与原始JSON一致；下载不含输入、密码或终端输出。注销后刷新应提示访问失败，不显示假成功。
