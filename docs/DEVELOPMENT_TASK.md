# 交给 Codex 的开发任务

开发并发布 **FnTerminal**：可以在飞牛 fnOS「应用中心 → 手动安装」上传的本地 FPK 原生 Web 终端应用。

请以本仓库源码为基础，按以下顺序执行：

1. 阅读官方飞牛开发手册 https://developer.fnnas.com/docs/ 中的 fnpack、Native 应用、统一网关、应用入口、权限、打包规范；对照本项目 `packaging/` 更正任何不匹配字段，保留 rootless 权限模型。
2. 校验 `go.mod` 版本，执行 `go mod tidy`，生成并提交 `go.sum`，执行 `go vet ./...`、`go test ./...`；检查 Go 和 JS 代码并修复编译错误。
3. 构建前端静态资源并离线内置，不准调用外部 CDN；在前端实现多标签终端、复制/粘贴、字号、深浅主题、手机端特殊键。
4. fnOS 入口优先走统一网关 `gatewayPrefix=/app/fnterminal`、`gatewaySocket=app.sock`，后端仅监听 Unix Socket，所有 HTTP 与 WS 只允许管理员；不要将 allUsers=false 当成服务端鉴权。
5. 检查 Socket 的 UDS 文件权限、属组、目标目录权限。`X-Trim-Userid`/`X-Trim-Isadmin` 只有在连接来自可信 fnOS 网关时才可采用。禁止 chmod 666、777；若鉴权模型不可确认，失败关闭。
6. 使用专属包用户创建 PTY；必须有最大并发数、会话超时、空闲回收、流量限制、服务关闭时子进程清理、审计元信息、超时以及安全错误提示。不得无条件提权、连接 Docker Socket 或自动开启 SSH。
7. 默认 NAS SSH 入口：首次打开显示可编辑主机、端口、用户名的连接弹窗；保存后，下次打开默认自动尝试最近使用的配置，并支持关闭自动连接。浏览器存储不可用时仍可临时连接。应用账户 Shell 仅在高级诊断中明确选择。支持自定义10022端口和数字开头用户名，经 NAS SSH 二次认证后进入对应用户会话。不得储存 NAS 密码或默认绕过主机密钥检查。
8. 用官方 `fnpack` 打出 x86 和 arm 的各自 `.fpk`，产物核对 manifest/校验和/资源目录，附 SHA256 和安装指引。
9. 在独立的 fnOS 测试机安装/启动/停止/升级/卸载，验证认证、PTY 功能、WebSocket、中文输入、普通用户拒绝访问、主机和应用账户权限隔离、重启稳定性。
10. 输出一份详细中文 README、打包脚本、CI 工作流和变更记录；标明测试结果，未经实测不要声称可直接生产使用。

### 验收标准

- [ ] 飞牛应用中心手动安装 FPK 成功；桌面出现终端图标
- [ ] 访问与当前 fnOS 登录域名同源，没有额外暴露终端 TCP 端口
- [ ] 已登录的管理员可以创建真正的 PTY、运行命令和调整窗口大小
- [ ] 未登录/普通用户无法通过 HTTP 或 WebSocket 访问终端
- [ ] 任何绕过 Unix Socket 网关的请求无法伪造管理员 Header
- [ ] 默认只能获得 package 用户权限；NAS 管理身份需要 SSH 二次认证
- [ ] 停止和卸载时所有子终端进程清理，重启后不残留
- [ ] 离线前端资源、无 CDN；支持中文、移动端可用
- [ ] 支持 amd64 和 arm64，发布两个 FPK（或验证 platform=all 真正可行后合包）
